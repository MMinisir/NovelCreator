# 小说创作辅助工具详细设计文档

> 版本：1.0  
> 定位：本地优先、方法论驱动、面向中文小说创作者的设定管理与 AI 辅助写作工具

---

## 一、产品概述

### 1.1 产品定位

面向小说作者（尤其是长篇连载、网文、类型小说作者）的**创作工作台**，提供从设定管理、大纲规划、时间线梳理到 AI 辅助生成的一站式解决方案。产品以“结构化写作方法论”为核心，强调“工具引导创作”而非“工具替代创作”。

### 1.2 核心价值

- **设定不再混乱**：人物、地点、事件、关系、状态全部结构化存储，随时查阅。
- **大纲有章可循**：内置雪花写作法、三幕式、角色弧光等成熟方法论，引导作者科学构建故事。
- **时间线直观可视**：解决长篇创作中时间错乱、事件顺序不清的痛点。
- **AI 辅助而非替代**：AI 用于灵感激发、重复性劳动和一致性提醒，不直接生成大段正文，避免“AI 味”。
- **本地优先，隐私安全**：所有数据存储在本地 IndexedDB，无需联网，支持 JSON 导入导出。

### 1.3 目标用户

- 网文作者（起点、晋江、番茄等平台）
- 传统小说作者（出版、文学创作）
- 剧本杀 / 互动叙事创作者
- 同人创作者

## 二、功能需求详述

### 2.1 项目管理

#### 2.1.1 项目列表

- 每个项目包含：书名、笔名/作者、类型（玄幻、都市、言情、悬疑等）、一句话简介、创建时间、最后修改时间。
- 支持项目封面图（本地图片或外链）。
- 支持项目搜索、排序、标签分类（如“连载中”“已完结”“构思中”）。

#### 2.1.2 项目设置

- **世界观设定**：力量体系、社会规则、种族、魔法/科技水平、历史背景等，以自由文本 + 标签形式存储。
- **叙事视角**：第一人称 / 第三人称 / 多视角等。
- **时间设定**：故事起始时间、时间流速（现实时间与故事时间比例）、是否允许模糊时间。
- **章节预设**：每章目标字数、章节命名规则（如“第X章 标题”）。

### 2.2 设定管理

#### 2.2.1 人物管理

**字段定义：**

| 字段 | 类型 | 说明 |
|------|------|------|
| 姓名 | 字符串 | 可设置多个别名 |
| 重要程度 | 枚举 | 主角 / 重要配角 / 配角 / 龙套 |
| 性别 / 年龄 | 字符串 | 支持模糊描述（如“外表20岁，实际300岁”） |
| 外貌描述 | 富文本 | 支持图片 |
| 性格标签 | 多选标签 | 可自定义标签体系（如 MBTI、九型人格、自定义） |
| 核心欲望 | 文本 | 角色最深层的动机 |
| 致命缺陷 | 文本 | 角色性格弱点 |
| 背景故事 | 富文本 | 包括出身、经历、关键转折 |
| 能力/技能 | 文本列表 | 可关联世界观设定 |
| 人物状态历史 | 数组 | 见下方状态模型 |
| 角色弧光 | 数组 | 见下方弧光模型 |
| 出场记录 | 关联事件 | 自动统计 |
| 备注 | 富文本 | 作者自由填写 |

**状态模型：**
```
{
  "timestamp": "第3章" | "2024-03-15" | "春天",
  "state": "受伤昏迷" | "升级" | "死亡" | "黑化" | 自定义,
  "description": "详细描述状态变化及原因",
  "related_event": "eventId" // 关联触发事件
}
```

**角色弧光模型：**
```
{
  "stage": "初始状态" | "触发事件" | "成长/堕落" | "高潮转变" | "最终状态",
  "description": "该阶段角色状态描述",
  "chapter_range": "第1-5章"
}
```

**UI 设计：**
- 人物卡片列表，卡片显示头像（可选）、姓名、重要程度、核心欲望、当前状态。
- 点击卡片进入详情页，详情页包含所有字段，状态历史以时间线形式展示。
- 支持人物关系快速添加（从详情页直接选择另一人物并设置关系）。

#### 2.2.2 人物关系

**关系模型：**
```
{
  "source_id": "characterId",
  "target_id": "characterId",
  "type": "亲情/友情/爱情/敌对/师徒/合作/利用/暗恋/仇恨/其他",
  "strength": -100 ~ +100, // 负数表示负面关系，正数表示正面关系
  "description": "关系描述",
  "dynamic": true, // 是否随剧情变化
  "history": [
    {
      "timestamp": "第X章",
      "strength": 50,
      "type": "友情",
      "note": "关系变化原因"
    }
  ]
}
```

**UI 设计：**
- 关系列表视图：表格展示所有关系，支持筛选、排序。
- 关系图视图：力导向图，节点大小按重要程度，连线颜色按关系类型（红=敌对，绿=友好），连线粗细按强度绝对值。
- 支持从关系图点击节点跳转人物详情，双击节点聚焦子图。

#### 2.2.3 地点管理

**字段：**

| 字段 | 类型 | 说明 |
|------|------|------|
| 名称 | 字符串 | |
| 类型 | 枚举 | 城市/建筑/自然/异界/虚拟空间/其他 |
| 描述 | 富文本 | 环境、氛围、特色 |
| 所属区域 | 关联地点 | 支持地点层级（如“长安城”包含“皇宫”“集市”） |
| 关联人物 | 多选关联 | 常驻或相关人物 |
| 关联事件 | 多选关联 | 发生在此地的事件 |
| 图片 | 图片 | 可选 |

**UI 设计：**
- 地点卡片视图，支持按类型筛选。
- 地点详情页展示关联人物和事件列表。
- 可选地图视图（自定义上传背景图，标记地点位置）。

#### 2.2.4 事件管理

**字段：**

| 字段 | 类型 | 说明 |
|------|------|------|
| 名称 | 字符串 | 事件标题 |
| 类型 | 枚举 | 主线/支线/日常/战斗/感情/转折/伏笔/回收等 |
| 描述 | 富文本 | 事件详细经过 |
| 时间戳 | 灵活时间 | 支持“第X章”“具体日期”“模糊时间（春天/三年后）” |
| 参与者 | 多选人物 | |
| 地点 | 单选地点 | |
| 结果 | 文本 | 事件造成的影响 |
| 关联伏笔 | 多选关联 | 埋设或回收的伏笔 |
| 重要性 | 星级 | 1-5星 |
| 排序权重 | 数字 | 用于同时间事件排序 |

**UI 设计：**
- 事件列表按时间线排序展示。
- 事件详情页可查看参与者、地点、结果、关联伏笔。
- 支持从事件快速跳转到人物或地点详情。

### 2.3 大纲系统

#### 2.3.1 多级大纲结构

- **故事核**：核心冲突 / 核心问题，作为项目根节点。
- **五句话梗概**：对应三幕式结构（开端、发展、高潮、转折、结局），每句一句话。
- **分幕/分卷**：根据故事长度，可分为三幕或更多卷，每卷有标题和概要。
- **章节细纲**：每章包含标题、核心剧情概述、关键事件引用、出场人物、伏笔埋设/回收。
- **场景清单**：每章可拆分多个场景，每个场景包含：场景目标、地点、人物、冲突、结果。

**数据结构：**
```
Outline
├── story_core: string
├── logline: string
├── synopsis: string
├── acts: [
│   {
│     "title": "第一幕",
│     "summary": "...",
│     "chapters": [
│       {
│         "title": "第1章 穿越",
│         "summary": "主角穿越到异世界，初步了解环境",
│         "key_events": ["eventId1", "eventId2"],
│         "foreshadowing_planted": ["fsId1"],
│         "foreshadowing_resolved": ["fsId2"],
│         "scenes": [
│           {
│             "goal": "展示主角困境",
│             "location": "locationId",
│             "characters": ["charId1"],
│             "conflict": "主角与环境的冲突",
│             "outcome": "主角决定活下去"
│           }
│         ]
│       }
│     ]
│   }
│ ]
```

**交互设计：**
- 树形大纲视图，支持展开/折叠、拖拽调整章节顺序、拖拽移动场景所属章节。
- 支持“一键生成五句话梗概”按钮（AI 辅助）。
- 章节节点显示关键事件标签、伏笔标签（未回收显示橙色，已回收显示绿色）。
- 大纲与正文分离，但可关联正文段落（如场景关联到具体正文文本）。

### 2.4 时间线系统

#### 2.4.1 时间表示

- **精确时间**：`2024-03-15 14:30`
- **章节时间**：`第3章`
- **模糊时间**：`春天`、`三年后`、`大战结束后`、`主角成年时`
- **相对时间**：`事件A发生前三天`

系统需要支持将以上时间统一映射到可排序的数值或逻辑顺序，模糊时间通过用户手动调整顺序。

#### 2.4.2 全局时间线

- 垂直时间线展示所有事件，按时间顺序排列。
- 支持筛选：按人物、地点、事件类型、时间范围。
- 事件节点显示：事件名称、时间、参与者头像（小图标）、地点。
- 点击事件节点弹出详情卡片。

#### 2.4.3 角色时间线

- 选择某个人物，展示该人物参与的所有事件，按时间排序。
- 同时展示该人物的状态变化点（来自人物状态历史），与事件对应。
- 角色时间线可用于检查角色行为是否合理、成长弧线是否清晰。

#### 2.4.4 多轨时间线（高级）

- 按人物或地点或事件类型分轨展示，类似视频剪辑软件的时间轴。
- 支持缩放、平移，查看全局或细节。
- 轨道可折叠/展开。

**UI 技术**：使用 D3.js 或自研 Canvas 渲染，初期可简化为垂直列表 + 缩放。

### 2.5 可视化功能

#### 2.5.1 人物关系图

- 力导向图，节点大小反映重要程度。
- 连线颜色：关系类型映射（如亲情=蓝色，友情=绿色，爱情=粉色，敌对=红色）。
- 连线粗细：关系强度绝对值。
- 连线标签：显示关系类型和强度（如“师徒 +80”）。
- 交互：
  - 悬停节点显示人物摘要。
  - 点击节点打开人物详情侧边栏。
  - 双击节点高亮其所有关系，其他节点淡化。
  - 支持拖拽节点调整布局。
  - 支持搜索框定位人物。
- 导出：PNG / SVG。

#### 2.5.2 时间线图

- 全局时间线（垂直/水平可切换）。
- 事件节点按时间排列，颜色按事件类型区分。
- 支持缩放、平移。
- 点击节点查看详情。
- 支持筛选和搜索。

#### 2.5.3 大纲结构图（可选）

- 将大纲以思维导图形式展示，从故事核展开到分幕、章节、场景。
- 可折叠、展开节点。

### 2.6 AI 辅助功能

#### 2.6.1 AI 服务基础架构

- **多模型支持**：OpenAI 兼容接口，可配置 DeepSeek、GPT、Claude、Kimi、通义千问等。
- **统一上下文构建器**：根据当前操作（如生成大纲）自动收集相关数据（项目设定、人物列表、已有大纲等）构建 Prompt 上下文。
- **流式输出**：所有生成类功能支持 SSE 流式返回，减少等待焦虑。
- **温度控制**：设定类生成使用较低温度（0.3-0.5），创意类生成使用较高温度（0.7-1.0）。
- **Token 管理**：自动估算上下文长度，超长时进行截断或摘要。

#### 2.6.2 AI 功能列表

##### （1）生成故事核与五句话梗概

- 输入：题材、类型、核心灵感（一句话）、主角设定（可选）。
- 输出：故事核（核心冲突）、五句话梗概（对应三幕式）。
- 提示词策略：
  - 要求 AI 遵循“冲突驱动”原则，给出核心问题。
  - 五句话梗概必须包含：开端、发展、高潮、转折、结局。
  - 每句话不超过 50 字。

##### （2）生成人物小传

- 输入：人物姓名、重要程度、已有性格标签（可选）。
- 输出：核心欲望、致命缺陷、背景故事、性格细节、口头禅。
- 提示词策略：
  - 要求基于已有世界观设定生成，避免违背设定。
  - 强调“缺陷”必须真实影响行为。

##### （3）生成人物关系建议

- 输入：人物列表（自动从项目读取）。
- 输出：建议的关系对（如“主角与反派：曾经同门，因理念分歧决裂，关系强度 -80”）。
- 提示词策略：
  - 要求关系有变化空间，不只给静态关系。
  - 给出关系变化的时间节点建议。

##### （4）生成时间线

- 输入：无序事件列表（用户手动输入或粘贴）。
- 输出：按时间排序的事件序列，并抽取时间表达。
- 提示词策略：
  - 识别模糊时间并给出排序建议，允许用户手动调整。
  - 输出为 JSON 格式便于导入。

##### （5）大纲扩展

- 输入：故事核 + 五句话梗概 + 分幕概要（可选）。
- 输出：详细章节细纲（每章标题、核心剧情、关键事件、伏笔建议）。
- 提示词策略：
  - 遵循“每章必须有冲突和转折，结尾留钩子”。
  - 根据作品类型调整节奏（如网文要求“黄金三章”）。

##### （6）场景生成

- 输入：场景目标、地点、人物、冲突。
- 输出：场景描写（环境、动作、对话建议），但**不直接输出完整正文**，而是提供关键描写片段和对话要点，作者自行整合。
- 提示词策略：
  - 避免陈词滥调，要求具体细节。
  - 保持与人物性格一致。

##### （7）伏笔检测与建议

- 输入：章节文本（用户粘贴或从写作区读取）。
- 输出：疑似伏笔（未回收的线索）、可回收的时机建议。
- 提示词策略：
  - 标注文本中可能被后续利用的细节。
  - 输出列表包含：伏笔描述、出现位置、建议回收章节。

##### （8）一致性检查

- 输入：指定章节范围或全文。
- 输出：检查报告，包含：
  - 人物性格前后矛盾点（如“第2章主角胆小，第10章突然勇敢且无转变过程”）。
  - 时间线冲突（如“事件A发生在春天，事件B发生在事件A后三天，但时间戳显示为冬天”）。
  - 设定冲突（如“世界观设定魔法需要吟唱，但第5章主角瞬发魔法”）。
  - 伏笔未回收提醒。
- 实现方式：结合规则引擎（对结构化数据做检查）和 LLM（对文本语义分析），并非纯 LLM。
- 提示词策略：
  - 分段检查，避免上下文过长。
  - 输出结构化报告，附原文引用。

##### （9）润色与改写

- 输入：选中文本。
- 功能：润色（提升文笔）、改写（换风格）、扩写、缩写。
- 支持自定义风格（如“古风”“轻松搞笑”“严肃文学”）。

#### 2.6.3 提示词管理

- **提示词模板库**：内置多个模板，按功能分类（大纲/人物/时间线/章节/润色等）。
- **变量系统**：模板中可使用变量，如 `{{project_name}}`、`{{character_list}}`、`{{outline}}`、`{{world_setting}}` 等，运行时自动替换。
- **自定义模板**：用户可创建、编辑、删除模板。
- **模板分享**：支持导出/导入 JSON，未来可接入社区。
- **版本管理**：记录模板修改历史，可回滚。

### 2.7 伏笔管理系统

#### 2.7.1 伏笔数据模型

```
{
  "id": "fs001",
  "description": "主角捡到的神秘戒指",
  "planted_at": {
    "chapter": "第3章",
    "scene": "场景ID",
    "text": "原文引用（可选）"
  },
  "expected_resolve_at": "第20章",
  "status": "active | resolved | abandoned",
  "resolved_at": {
    "chapter": "第21章",
    "scene": "场景ID",
    "text": "原文引用（可选）"
  },
  "related_characters": ["charId1"],
  "related_events": ["eventId1"],
  "priority": "high | medium | low"
}
```

#### 2.7.2 功能设计

- 伏笔列表：按状态筛选（活跃/已回收/废弃）、按优先级排序。
- 伏笔时间线：在全局时间线上标记伏笔埋设和回收位置。
- 超期提醒：当预期回收时间已过且状态仍为活跃时，在项目首页显示提醒。
- 自动回收建议：AI 分析当前章节进度和未回收伏笔，给出回收时机建议。
- 伏笔关联：从章节大纲或正文中手动添加伏笔，或通过 AI 检测自动添加候选。

### 2.8 写作区与正文管理

虽然本工具重点在设定和大纲，但为了闭环，需要提供基础写作功能。

#### 2.8.1 写作界面

- 分屏模式：左侧大纲/设定参考，右侧编辑器。
- 编辑器支持 Markdown 语法，实时预览。
- 支持章内场景标签，可将正文段落关联到具体场景。
- 自动保存到 IndexedDB，记录修改历史。

#### 2.8.2 章节管理

- 章节列表与大纲章节对应。
- 支持章节状态（未开始/草稿/已完成/已修改）。
- 字数统计、目标字数进度条。
- 版本历史：保存每次手动保存或自动保存的版本，支持对比和回滚。

#### 2.8.3 一致性提醒（写作时）

- 在写作过程中，如果输入的文字涉及已有人物状态变化（如“主角突然会飞”），可触发提醒（需预先定义人物能力）。
- 提供侧边栏显示当前场景的相关设定（人物当前状态、地点描述、关联伏笔），避免作者翻找。

### 2.9 导入导出与数据管理

#### 2.9.1 导入

- 支持从 TXT、Markdown、JSON、DOCX 导入正文或设定。
- 导入设定时，可解析特定格式（如 `@人物: 姓名, 重要程度, 描述`）。
- 导入正文时，自动按章节标题拆分。

#### 2.9.2 导出

- 导出整个项目为 JSON（包含所有设定、大纲、正文）。
- 导出正文为 TXT / Markdown / DOCX / EPUB。
- 导出人物关系图为 PNG / SVG。
- 导出时间线为图片或 CSV。
- 导出大纲为 Markdown 或 OPML（思维导图软件可读）。

#### 2.9.3 数据备份与恢复

- 自动本地备份（IndexedDB 定时备份到文件，需用户授权下载）。
- 手动备份：一键导出完整 JSON。
- 恢复：从 JSON 导入，校验版本兼容性。

### 2.10 写作数据分析（可选高级功能）

- **字数统计**：总字数、日均字数、每章字数分布。
- **人物出场频率**：统计每个人物在正文中出现的次数，生成柱状图。
- **章节节奏分析**：根据每章事件数量和冲突强度，估算节奏曲线，提示“连续平淡章节”。
- **设定利用率**：统计地点、人物、伏笔在正文中的实际使用情况，找出“设定冗余”。
- 这些功能可作为后续版本迭代，不在初始版本强制实现。

## 三、写作方法论集成

产品内置以下方法论模板，引导用户按流程使用：

### 3.1 故事核设计引导

当用户创建新项目时，首先要求填写：
1. 主角是谁？
2. 主角想要什么？
3. 谁/什么阻碍他？
4. 如果失败会怎样？
5. 故事的核心冲突是什么？

系统根据回答自动生成“故事核”并存储为项目根节点。

### 3.2 雪花写作法流程

提供“雪花模式”引导：
1. 写一句话梗概（不超过 25 字）。
2. 扩展为五句话段落（包含开端、发展、高潮、转折、结局）。
3. 为每个主要角色写一段描述（动机、目标、冲突、顿悟）。
4. 将五句话段落扩展为五页大纲（每句话扩展为一页）。
5. 生成场景清单。

系统在每个步骤提供输入框、提示和 AI 辅助按钮，步骤间自动保存并关联。

### 3.3 角色弧光模板

内置常见弧光类型：
- 正向弧光：缺陷 → 成长 → 转变 → 克服。
- 负向弧光：理想 → 堕落 → 悲剧。
- 平弧：坚持信念 → 改变世界。

用户选择类型后，系统提供对应的阶段填写模板，并关联人物状态历史。

### 3.4 中文网文专属模板

针对网文作者的预设：

- **黄金三章**：第一章冲突引入、第二章金手指/转折、第三章悬念钩子。
- **爽点节奏表**：每 3-5 章一个小高潮，每 10-15 章一个大高潮。
- **打脸反转模板**：铺垫 → 压制 → 反击 → 收获。
- **升级体系模板**：境界划分、升级条件、每章升级进度。
- **感情线模板**：相遇 → 误会 → 升温 → 波折 → 确认。

这些模板会在大纲生成时作为可选项，AI 会参考模板结构输出。

### 4.1 核心实体关系图

```

Event *─1 Location
Event *─* Foreshadowing

```

### 4.2 模糊时间处理策略

- 时间戳字段支持多种格式：精确日期、章节号、模糊描述。
- 系统维护一个“时间排序索引”，用户可手动调整模糊时间的先后顺序。
- 当 AI 生成时间线时，输出排序建议，用户确认后写入索引。

### 4.3 一致性检查规则引擎

对于结构化数据，可进行规则检查（无需 LLM）：
- 人物死亡后仍出现在后续事件中 → 警告。
- 事件时间早于人物出生时间 → 警告。
- 地点层级关系矛盾（如 A 包含 B，但事件中 B 在 A 外部）。
- 伏笔状态为 active，但关联事件已在文本中明确回收（需要文本分析辅助）。

规则引擎产生结构化警告，LLM 负责语义层面检查。

## 五、技术架构细化

### 5.1 前端架构

- **框架**：React 18 + TypeScript
- **构建工具**：Vite
- **UI 库**：Tailwind CSS + Headless UI / Radix UI
- **状态管理**：Zustand（项目数据、UI 状态）、Immer（不可变更新）
- **路由**：React Router
- **可视化**：
  - 关系图：D3.js（力导向图，Canvas 渲染）
  - 时间线：自研组件（初期用垂直列表，后期可扩展为 Canvas 时间轴）
  - 图表：Recharts（字数统计、节奏分析）
- **编辑器**：TipTap（基于 ProseMirror，支持 Markdown 快捷键和富文本）
- **存储**：Dexie.js（IndexedDB 封装）

### 5.2 数据存储设计

使用 IndexedDB，数据库名 `novel-tool`，版本号 `1`。

**Object Stores：**

| Store 名称 | 主键 | 索引 |
|-----------|------|------|
| projects | id | name, updatedAt |
| characters | id | projectId, importance |
| locations | id | projectId, type |
| events | id | projectId, timestamp, type |
| relationships | id | sourceId, targetId, projectId |
| states | id | characterId, timestamp |
| arcs | id | characterId, stage |
| outline_nodes | id | projectId, parentId, order |
| foreshadowings | id | projectId, status |
| chapters | id | projectId, order |
| scenes | id | chapterId, order |
| prompt_templates | id | category |
| settings | projectId | |

所有数据均以 JSON 序列化存储，便于导出导入。

**数据迁移策略**：内置版本号，每次结构变更时提供迁移函数，从旧版本读取并转换。

### 5.3 AI 服务层

- 抽象 `AIProvider` 接口：
  - `generate(prompt, options): AsyncIterable<string>`
  - `chat(messages, options): AsyncIterable<string>`
- 实现 OpenAI 兼容 Provider（可配置 baseURL、apiKey、model）。
- 上下文构建器：根据功能需要，从 store 中拉取相关数据，组装为 system prompt 和 user prompt。
- Token 估算：使用 `gpt-tokenizer` 或近似估算，超出限制时自动截断中间部分或使用摘要。
- 缓存：对于相同输入和参数的生成请求，可缓存结果（本地），减少 API 调用。

### 5.4 离线与同步

- 所有功能离线可用（除 AI 生成需要网络）。
- 数据本地存储，无后端。
- 未来如需多设备同步，可导出加密 JSON 文件至云盘（用户自行操作），不内置云同步。

## 六、交互设计要点

### 6.1 全局布局

- 左侧导航栏：项目、人物、地点、事件、大纲、时间线、关系图、伏笔、写作区、设置。
- 顶部工具栏：项目切换、全局搜索、导入导出、AI 助手入口。
- 主内容区：根据导航切换。
- 右侧浮动面板：当前选中项的快速详情、AI 建议。

### 6.2 关键交互流程

#### 流程 1：新建项目并生成大纲

1. 点击“新建项目”，填写书名、类型、一句话灵感。
2. 进入“故事核”页面，按引导填写五个问题。
3. 点击“AI 生成五句话梗概”，系统调用 AI，返回结果填入对应输入框，用户可编辑。
4. 点击“生成分幕”，AI 基于梗概生成三幕概要。
5. 用户手动调整或继续“AI 生成章节细纲”。
6. 大纲树生成，用户可拖拽调整。

#### 流程 2：添加人物并建立关系

1. 点击“添加人物”，填写基本信息。
2. 在人物详情页点击“添加关系”，选择另一人物，设置关系类型和强度。
3. 系统自动创建双向关系记录（可设置为单向，如暗恋）。
4. 关系图自动更新。

#### 流程 3：从正文提取时间线

1. 在写作区粘贴或输入一段文本。
2. 点击“提取时间线事件”，AI 分析文本中的时间表达和事件。
3. 返回事件列表（含时间、参与者、地点建议），用户确认后批量导入事件库。
4. 时间线自动更新。

#### 流程 4：伏笔管理

1. 在写作时，选中一段文字，右键“标记为伏笔”。
2. 填写伏笔描述、预期回收章节。
3. 伏笔出现在伏笔列表和时间线上。
4. 当章节进度超过预期回收时间，首页出现提醒。
5. 在后续章节中回收伏笔时，选中对应文字，右键“标记为伏笔回收”，选择对应伏笔。

### 6.3 搜索与过滤

- 全局搜索：支持搜索人物、地点、事件、大纲、正文内容。
- 各模块内高级过滤：按类型、标签、时间范围、状态过滤。
- 搜索结果高亮显示。

## 七、非功能需求

### 7.1 性能

- 人物数量 ≤ 500，事件 ≤ 2000，章节 ≤ 1000 时，界面操作流畅（60fps）。
- 关系图渲染 500 节点时不卡顿（使用 Canvas + 力导向布局优化）。
- 时间线加载 1000 事件时延迟 < 1s。

### 7.2 兼容性

- 支持最新版 Chrome、Edge、Firefox、Safari。
- 桌面端优先，移动端仅提供查看功能（后续适配）。

### 7.3 安全性

- 数据完全本地，不经过服务器。
- AI 调用使用用户自行配置的 API Key，不存储在任何服务器。
- 支持数据加密导出（可选密码保护）。

### 7.4 可扩展性

- 数据模型预留自定义字段（如人物可添加自定义属性）。
- 支持插件式提示词模板，未来可开放社区共享。

## 八、实现注意事项与风险应对

### 8.1 数据模型演进的灵活性

- 使用 JSON 存储，避免严格关系型约束。
- 提供导入时自动迁移旧版本数据。
- 在设置中提供“数据修复”工具，可重建索引和关系。

### 8.2 AI 生成质量不稳定

- 所有 AI 输出均可编辑，不自动覆盖已有内容。
- 提供“重新生成”和“回退上一版”按钮。
- 系统在生成前可显示将使用的 Prompt 预览，高级用户可修改。

### 8.3 用户维护成本过高

- 减少必填字段，大部分字段可选。
- 支持批量导入设定。
- 提供“快速录入”模式：在任意页面用 `@` 快捷键快速创建人物/地点/事件。

### 8.4 与现有工具差异化

- 内置写作方法论引导（而非单纯提供空白表单）。
- 中文网文模板深度定制。
- 本地优先，无账户体系，即开即用。
- 强调“辅助”而非“替代”，AI 只提供素材和检查，不直接生成大段正文。
