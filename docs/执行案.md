# 小说创作辅助工具敏捷开发执行案（优化版）

## 1. 优化要点说明

基于原执行案评估，本版本进行以下关键优化：

- **前置数据模型设计**：在 Sprint 0 完成核心实体建模，避免后续返工。
- **重新校准故事点**：拆分过大用户故事，修正估算，预留缓冲。
- **AI 架构提前**：将 AI 服务层技术预研提前至 Sprint 5，功能开放保持 Sprint 7。
- **轻量 PWA 提前**：在 Sprint 6 实现灵感速记与离线查看，快速验证移动端价值。
- **采用成熟虚拟滚动库**：降低自研风险，保证时间线性能。
- **补充协作功能**：在后期 Sprint 加入评论与批注，覆盖设计文档协作需求。
- **强化用户反馈闭环**：每个 Sprint 评审引入种子用户，动态调整 Backlog。

---

## 2. 产品愿景与成功标准（不变）

**产品愿景**  
打造一款本地优先、方法论驱动、面向中文小说创作者的设定管理与 AI 辅助写作工作台。让作者专注于创作本身，通过结构化工具和智能辅助降低维护成本，从“管理型数据库”升级为“服务型创作工作台”。

**成功标准（MVP 验收）**  
- 作者能够创建项目，录入基础设定（人物、地点），编写正文并自动保存至本地。
- 核心数据（人物、地点、事件、关系）支持增删改查，人物关系图可基本可视化。
- 支持手动备份与恢复（JSON 导出/导入）。
- 界面简洁，核心操作路径不超过 3 次点击。

**远期成功标准**  
- AI 辅助功能（生成设定、一致性检查等）稳定可用，且用户可配置多个模型。
- 时间线、大纲、伏笔管理、移动端速记等功能完善，形成创作闭环。
- 用户数据自主可控，备份与同步机制可靠。

---

## 3. 敏捷方法与团队结构（不变）

采用 **Scrum** 框架，迭代长度 **2 周**。团队规模 6-8 人，角色如下：

| 角色 | 职责 | 人员配置 |
|------|------|----------|
| 产品负责人 | 维护产品 Backlog，定义用户故事优先级，验收交付 | 1 人 |
| 开发团队 | 前端开发、测试、UI/UX | 4-5 人（含 1 名测试） |
| Scrum Master | 主持迭代会议，移除障碍，保证流程 | 1 人（可兼任开发） |
| UX 设计师 | 交互设计与可用性测试 | 1 人（外部协作，按需参与） |

**技术栈**：React 18 + TypeScript + Vite + Tailwind CSS + Zustand + Dexie.js + TipTap + Cytoscape.js + react-window。

## 5. 迭代计划（优化版）

### Sprint 0（预备，1 周）
- **目标**：环境搭建、技术选型确认、整体数据模型设计、基础 UI 框架、项目脚手架。
- **任务**：
  - 初始化 Vite + React + TS 项目，集成 Tailwind、Zustand、Dexie、TipTap，建立路由和全局布局。
  - **设计所有核心实体的 TypeScript 接口、IndexedDB Schema、关联索引、JSON 导出格式**（人物、地点、事件、关系、大纲、章节、伏笔、灵感碎片）。
  - 技术预研：TipTap 编辑器集成、Dexie 基础操作、File System Access API 可行性。
- **交付物**：可运行的空应用，具备基本导航框架，数据模型文档与类型定义。

### Sprint 1（2 周）
- **目标**：实现 MVP 核心——项目管理与本地存储。
- **用户故事**：US-001、US-002、US-003、US-004、US-005。
- **任务分解**：
  - 实现项目 CRUD，项目列表页面。
  - 实现导出/导入 JSON（基于已定义数据模型）。
  - 编写数据访问层（Repository 模式），为后续实体提供统一接口。
- **验收**：用户可创建项目、打开项目、导出/导入项目，数据持久化。

### Sprint 2（2 周）
- **目标**：实现人物、地点、事件的基础设定管理。
- **用户故事**：US-101、US-102、US-105、US-106、US-107。
- **任务分解**：
  - 人物列表与详情编辑页面（富文本采用 TipTap 轻量配置）。
  - 地点列表与详情编辑页面。
  - 事件列表与详情编辑页面（时间戳先支持简单格式）。
  - 人物关系创建与管理页面（列表视图）。
- **验收**：用户可以创建和管理核心设定，关系可建立。

### Sprint 3（2 周）
- **目标**：实现大纲系统和基础写作区。
- **用户故事**：US-201、US-202、US-203、US-204、US-501a、US-501c。
- **任务分解**：
  - 设计大纲树数据结构与组件。
  - 实现故事核、五句话梗概、分幕/章节细纲的编辑。
  - 集成 TipTap 编辑器（基础 Markdown），实现章节正文写作，自动保存。
  - 章节列表与状态管理。
- **验收**：作者可以建立大纲结构，并开始写正文，自动保存。

### Sprint 4（2 周）
- **目标**：完善设定管理（人物状态历史、快速录入），增加关系图可视化。
- **用户故事**：US-104、US-108、US-401、US-402。
- **任务分解**：
  - 人物状态历史存储与展示（当前状态卡片）。
  - 实现“@”快速创建人物解析（基于简单规则或正则，不依赖 AI）。

- **正式 1.0 版本（Sprint 8 完成后）**：包含 AI 核心功能、写作辅助、一致性检查（规则引擎）、自动备份恢复。满足设计文档主要需求。
- **后续版本（Sprint 9-10 及以后）**：移动端完善、AI 增强、协作、数据分析、故事体检报告等。

## 7. 质量保证策略（调整）

- **定义完成（DoD）**（不变，增加数据模型变更评审）：
  - 代码通过代码审查。
  - 单元测试覆盖核心逻辑（数据存储、排序、解析、AI 上下文构建）。
  - 用户故事验收标准全部通过。
  - 关键交互在主流浏览器（Chrome/Edge/Firefox）测试通过。
  - 性能指标达到要求（列表 2000 条流畅滚动、关系图 500 节点不卡顿）。
  - 无严重或高优先级缺陷。
  - 任何数据模型变更需经过产品负责人和架构评审。

- **测试方法**：
  - **单元测试**：Jest + React Testing Library，重点测试数据模型、状态管理、解析逻辑、AI 上下文构建器。
  - **端到端测试**：Playwright，覆盖核心用户流程（创建项目→添加人物→写正文→导出→备份恢复）。
  - **性能测试**：手动压测大数据量，利用 Chrome DevTools 监控；时间线使用 2000 事件压测，关系图 500 节点压测。
  - **可用性测试**：每个 Sprint 评审时邀请 1-2 名种子用户进行 15 分钟体验，收集反馈。产品负责人将反馈转化为 Backlog 项，下个 Sprint 排期。

- **代码管理**：Git，采用 trunk-based development，短分支，CI 自动运行测试和构建。

## 10. 总结

本优化版执行案在保持原框架的基础上，针对评估风险进行了务实调整：**前置数据模型设计、拆分故事点、提前 AI 架构与 PWA、采用成熟库、补充协作功能、强化反馈闭环**。这样的调整使得迭代节奏更稳健，技术风险更可控，用户价值尽早体现，最终交付一个真正解决小说创作者痛点的服务型创作工作台。
